how to read

A card is a package. A slip under it is one thing the package exposes: a type, a trait, a function, or a small group of methods that belong together. Signatures are written as they are published — ~ marks a labelled argument, ? an optional one.

struct pub(all) struct Mailbox { name : String?; address : String }

One address. name is the display name when the letter carried one — “Leo” <leo@example.com> — and none otherwise.

enum pub(all) enum Address { Mailbox(Mailbox); Group(name~ : String, members~ : Array[Mailbox]) }

A single mailbox, or a named group. Groups survive a parse and are written back as written.

fn pub fn parse_address(StringView) -> Address raise Refused pub fn parse_addresses(StringView) -> Array[Address] raise Refused

Read a header line into addresses. Quoted local parts, comments and obsolete routes are accepted; anything else raises with the offset it gave up at.

struct pub struct Headers
  • new() -> HeadersAn empty table.
  • get(name) -> String?The first value, unfolded, or none.
  • all(name) -> Array[String]Every value in the order it arrived.
  • add / set / removeAppend, replace in place, drop every value.
  • iter()Walk the table in wire order, names as received.

Ordered, case-insensitive on the name, multi-valued. Values are stored with their folding removed.

enum pub(all) enum Body { Leaf(Bytes); Multipart(Array[Message]); Embedded(Message) }
  • LeafContent with its transfer encoding already undone.
  • MultipartParts in order; the boundary lives in Content-Type.
  • EmbeddedA whole letter inside a letter, message/rfc822.
struct pub(all) struct Message { headers : Headers; body : Body }

A part is a message too, so the type nests without a second shape for “part”.

fn Message::parse(BytesView, strict? : Bool) -> Message raise Refused

Read a letter from its bytes. Lenient by default: a missing boundary ends the parts instead of failing. strict turns every such recovery into a raise.

fn Message::encode(Self, utf8? : Bool) -> Bytes

Write the letter back with CRLF line endings, folded at 78 columns. utf8 writes non-ASCII in place; without it every such header becomes an encoded word.

Round trip. Parse then encode, then parse again, gives the same tree — and encoding that tree a second time gives the same bytes.

readers subject · from · to · cc · bcc · reply_to · date · message_id · content_type · text · html · attachments

Each reads one header and hands back a typed value: addresses are decoded, date is a date-time, content_type is a media type. text and html pick the best part for the charset actually declared; attachments walks the tree and collects the leaves that are not the body.

fn Message::new(from~ : Mailbox, to~ : Array[Address], subject~ : String, text? : String, html? : String, attachments? : Array[Attachment], cc? : Array[Address], date? : DateTime, message_id? : String) -> Message

Build a letter and let it choose the nesting: plain text alone stays flat, text with HTML becomes alternative, and anything with attachments becomes mixed — or related when the attachments are inline and referenced by id.

struct pub(all) struct Attachment { name : String; media_type : String; data : Bytes; inline : Bool; id : String? }

inline keeps the part inside the body; id is the content id an HTML part refers to.

suberror pub(all) suberror Refused { Header(at~ : Int); Address(at~ : Int); Boundary(at~ : Int); Encoding(at~ : Int); Charset(name~ : String) }

Every failure carries where it happened. at is a byte offset into the input, so a parser can point at the line that broke.

trait pub(open) trait Charset

UTF-8, US-ASCII and ISO-8859-1 are built in. Anything else is yours to add: implement the trait and hand the instance to the parser. A charset nobody registered raises Refused.Charset.

enum pub(all) enum Canon { Simple; Relaxed }

How whitespace and header case are normalised before hashing. Simple changes nothing; Relaxed collapses runs of spaces and lowercases names.

enum pub(all) enum Key { Rsa(PrivateKey); Ed25519(PrivateKey) }

RSA-SHA256 and Ed25519-SHA256. The variant decides both the algorithm tag and how the signature is laid out in base64.

value pub let signed : Array[String]

The header names signed when you do not pass your own list: from, to, subject, date, message-id and the rest of the usual set. Pass headers to override it.

fn pub fn sign(message : BytesView, key : Key, domain~ : String, selector~ : String, headers? : Array[String], header_canon~ : Canon = Relaxed, body_canon~ : Canon = Simple, timestamp? : Int64, expire? : Int64, length~ : Bool = false, identity? : String) -> String raise Refused

Returns one complete DKIM-Signature line, unfolded, without a trailing CRLF. length adds the l= tag that limits the body hash; identity sets i=.

fn pub fn verify(message : BytesView, lookup : (String) -> String? raise, now~ : Int64) -> Array[Verdict]

lookup turns a selector and domain into the published public key; you do the DNS. now is what t= and x= are checked against. Every signature in the letter gets a verdict, in order.

enum pub(all) enum Verdict { Pass(domain~ : String, selector~ : String); Fail(domain~ : String, reason~ : String); PermError(String); TempError(String) }

Fail means the signature did not verify — say the body changed. PermError and TempError mean the key could not be used, permanently or for now.

trait pub(open) trait Mechanism { name(Self) -> String; start(Self) -> Bytes?; step(Self, BytesView) -> Bytes raise Refused; finish(Self) -> Unit raise Refused = _ }

Four methods and no more. start returns none when the server speaks first; finish is where SCRAM checks the server’s own signature. Bytes in, bytes out — base64 is the protocol’s job, not yours.

struct Plain::new(user, password, authzid?)

The one everyone has. Sends authzid\0authcid\0password in a single step.

struct Login · CramMd5

The two other plain-ish ones. Login is the old two-challenge form; CramMd5 never sends the password, only a digest of a server nonce.

struct XOAuth2 · OAuthBearer::new(token, username?, host?, port?)

Bearer tokens for the two shapes in the wild: Google’s three-field string, and the standard single-field form with an optional host and port.

struct ScramSha256::new(user, password, nonce~)

A full SCRAM exchange: client-first, server-first, client-final, server-final. nonce is yours to supply — this package never reaches for a random source.

fn pub fn prep(StringView, unassigned? : Bool) -> String raise Refused

SASLprep: normalise a password or user name before it goes into a mechanism. Prohibited characters raise Refused.Prep with the character that was refused.

fn pub fn respond(&Mechanism, StringView) -> String raise Refused

Base64 challenge in, base64 answer out. Use this when you are driving the exchange yourself instead of handing the mechanism to a client.

suberror pub(all) suberror Refused { Prep(Char); Malformed(String); Server(String); Signature }

Signature is the one that matters: the server proved it does not know the password. Treat it as a hard stop, not a retry.

used by smtp::Client::auth(&Mechanism) · imap::Client::authenticate(&Mechanism) · pop3::Client::auth(&Mechanism)

All three protocols take the same trait object, so a mechanism written once works on all of them.

struct pub(all) struct Reply { code : Int; lines : Array[String] }
  • new(Int, String)Build a reply to hand to the server side.
  • text() -> StringThe lines joined with spaces, code removed.
  • status() -> String?The enhanced code, e.g. 2.1.5.
  • is_ok() -> BoolTrue for 2xx.
  • encode() -> BytesThe wire form, multi-line when there are several lines.
struct pub(all) struct Limits { line : Int; recipients : Int; size : Int64 } pub let limits : Limits

The defaults: a 12288-byte line so a SASL exchange always fits, 1000 recipients, and a 10 MB message.

suberror pub(all) suberror Refused { Malformed(String); Exceeded(limit~ : Int, got~ : Int); Order(String); Unsupported(String) }

Client-side mistakes, raised at queue time rather than on the wire: a command out of order, or an extension the server did not announce.

struct Client::new(lmtp? : Bool, limits? : Limits)

A client with nothing sent yet. Nothing here touches a socket: you feed it bytes and drain what it wants written.

session ehlo(name) · helo(name) · starttls() · auth(&Mechanism) · rset() · noop() · vrfy(s) · expn(s) · help() · quit()

Opening, securing and closing a session. ehlo records the extension map that every later command consults.

envelope mail(from, size?, body? : Body, utf8?, ret? : Ret, envid?, auth?) · rcpt(to, notify? : Array[Notify], orcpt?)

The envelope, one recipient at a time. ret, envid, auth and notify are DSN parameters and are dropped if the server did not offer DSN.

body data(BytesView) · bdat(BytesView, last?) · send(from, Array[to], BytesView)

data holds the body until the server says 354, then adds the missing CRLF and the dot-stuffing. bdat is the CHUNKING path. send is all of it in one call, adding SIZE, BODY=8BITMIME and SMTPUTF8 by itself when the server has them.

state feed(BytesView) -> Array[Event] raise Refused · next_write() -> Bytes?

The whole I/O contract, in two calls. Feed what arrived, drain what must go out. next_write returns none when the client is waiting on the server.

state extensions() -> Map[String, String] · has(String) -> Bool

What the last EHLO announced, keyed by name. has is the check the client itself uses before it dares to send an extension command.

enum pub(all) enum Event { Reply(Command, Reply); Sasl(sasl.Refused) } pub(all) enum Command { Greeting; Hello(String); StartTls; Auth(String); Mail(String); Rcpt(String); Data; Bdat(Int); Delivery(String); Rset; Noop; Vrfy(String); Expn(String); Help; Quit }

Every final reply arrives paired with the command it answered, so you never track the queue yourself. 334 and 354 are consumed inside the machine and do not surface.

struct Server::new(String, lmtp? : Bool, starttls? : Bool, auth? : Array[String], greeting? : String, limits? : Limits)

A server that answers syntax, order, size and the 354 dance by itself. You only see the requests that need a judgment call.

server feed(BytesView) · next() -> Request? · accept() · reply(Int, String) · challenge(BytesView) · next_write() -> Bytes? · closed() -> Bool

next returns none while a request is still waiting for your answer. challenge is the SASL continuation. In LMTP, Data is answered once per accepted recipient.

enum pub(all) enum Request { Hello(String, extended~ : Bool); StartTls; Auth(String, Bytes?); Response(Bytes); Mail(String, Map[String, String?]); Rcpt(String, Map[String, String?]); Data(Bytes); Vrfy(String); Expn(String); Rset; Quit }

What the application actually decides: who may relay, which mailbox exists, whether to accept the body. Rset and Quit are already answered and are only reported.

enum pub(all) enum Value { Nil; Number(Int64); Atom(String); Text(Bytes); List(Array[Value]) }

The response grammar in five cases. Anything the machine does not recognise still lands here, so a FETCH data item you did not expect is readable rather than lost.

enum pub(all) enum Status { Ok; No; Bad }

How a tagged command ended. No is a refusal; Bad is your command being wrong.

enum pub(all) enum Code { Alert; Capability(Array[String]); PermanentFlags(Array[String]); ReadOnly; ReadWrite; TryCreate; UidNext(Int64); UidValidity(Int64); HighestModseq(Int64); NoModseq; Modified(String); AppendUid(Int64, Int64); CopyUid(Int64, String, String); Closed; Other(String, String?) }

The bracketed codes. Uid and modseq bookkeeping you need for CONDSTORE arrives here rather than as a separate call.

enum pub(all) enum Response { Condition(String, Code?, String); Capability(Array[String]); Enabled(Array[String]); Flags(Array[String]); Exists(Int64); Expunge(Int64); List(flags~ : Array[String], delimiter~ : String?, name~ : String); Status(String, Map[String, Int64]); Esearch(tag~ : String?, uid~ : Bool, items~ : Map[String, Value]); Search(Array[Int64], modseq~ : Int64?); Fetch(Int64, Map[String, Value]); Namespace(Value); Other(String, Array[Value]) }

Untagged responses, one variant per shape in the spec. FETCH keys keep their original spelling, so BODY[HEADER.FIELDS (FROM)] stays exactly that.

enum pub(all) enum Event { Data(Response); Done(Int, Status, Code?, String); Sasl(sasl.Refused) }

Done carries the tag of the command that finished, so a caller that reuses one client for several commands can pair them up by number.

struct Client::new(limits? : Limits)

Each command you send is queued and returns its tag number. Responses come back through feed in arrival order.

session login(user, password) · authenticate(&Mechanism) · starttls() · capability() · enable(Array[String]) · noop() · logout()

enable is how UTF8=ACCEPT and CONDSTORE are turned on. A server that never announced them answers Bad, which arrives as a Status rather than a raise.

mailbox select(name, condstore?) · examine(name) · create · delete · rename · subscribe · unsubscribe · list(reference, pattern) · namespace · status(name, Array[String])

Names are UTF-8 and are quoted or sent as a literal for you. Against a server that only speaks rev1 and has not enabled UTF8=ACCEPT, the name is written in modified UTF-7 instead.

messages append(name, BytesView, flags?, date?) · idle() · done() · close() · unselect() · expunge()

append sends a literal, and pipelines it straight away when LITERAL+ or LITERAL- was announced. idle keeps the connection open; done ends it and returns you to normal command flow.

search search(criteria, uid?) · fetch(set, items, uid?, changedsince?) · store(set, action, uid?, unchangedsince?) · copy · move · uid_expunge

Sets and criteria are passed as the text you would type; this layer does not second-guess the grammar. changedsince and unchangedsince are the CONDSTORE arguments.

state feed(BytesView) -> Array[Event] raise Refused · next_write() -> Bytes? · capabilities() -> Array[String] · state() -> State

state is one of NotAuthenticated, Authenticated, Selected(name) or Logout — the same four the protocol itself names.

struct Client::new(limits? : Limits)

Commands queue; a group only goes out together when the server announced PIPELINING.

session user · pass · apop · auth(&Mechanism) · stls · capa · noop · quit

apop digests the timestamp from the greeting; stls upgrades the connection if CAPA listed it.

mailbox stat() · list(message?) · uidl(message?) · retr(n) · top(n, lines) · dele(n) · rset()

Counting, listing, fetching and marking. dele only marks: the message disappears when the session ends with QUIT, and rset takes the marks back.

state feed(BytesView) -> Array[Event] raise Refused · next_write() -> Bytes? · pending() -> Int

pending tells you how many commands are still unanswered, which is the whole of what back-pressure needs here.

enum pub(all) enum Event { Reply(Command, Reply); Sasl(sasl.Refused) } pub(all) enum Reply { Greeting(text~ : String, timestamp~ : String?); Ok(String); Err(String); Stat(count~ : Int, size~ : Int64); Listing(Array[(Int, Int64)]); Uids(Array[(Int, String)]); Content(Bytes); Capabilities(Array[String]) }

The greeting carries the timestamp APOP needs. Content is a whole message with the dot-stuffing already removed.

module Smtp::connect(host, port, security) · Smtp::send(message)

Open the connection with implicit TLS or plain TCP, negotiate STARTTLS if that is what you asked for, authenticate, then hand over a whole message.

module Smtp · Imap · Pop3

One session type per protocol, each holding a connection and the matching state machine from the package above it.

module security : None · StartTls · Tls

The three shapes a connection takes. STARTTLS is negotiated in the clear, then the socket is upgraded in place.

module limits · timeouts

Line, recipient and size limits follow the client you drive; connect and read timeouts belong here, because this is the only layer that can block.
